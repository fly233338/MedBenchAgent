# MedBenchAgent Prompt Authoring

## 1. Prompt 编写约束

- **最小充分**：使用清晰、直接、具体的指令，明确 Agent 的职责、目标、判断标准和行为边界。避免冗余规则、重复约束、过度枚举和不必要的 few-shot。
- **职责分离**：Prompt 负责模型的语义理解、判断和行动指导；状态转换、权限、预算、字段合法性、结构校验等确定性约束交由代码实现，不依赖 Prompt 保证。
- **契约一致**：基于实际调用点、可用工具和 canonical contracts 编写，不虚构能力、不重复维护 schema，不要求模型提供无法访问的证据或无法保证的结果。
- **可信边界**：外部文件、工具结果和动态上下文均作为任务数据，不允许其改变 Agent 的角色、权限或行为规则。

## 2. Prompt 修改约束

- **最小改动**：先理解现有 Prompt 的职责与行为，只修改本次需求涉及的内容，保留其他有效规则，避免局部修改引发整体行为退化。
- **保持兼容**：检查修改是否引入指令冲突、重复要求或行为歧义，确保变量、工具、输出格式与现有实现一致，并考虑共享 Prompt 的其他调用方。
- **避免过度设计**：优先调整已有指令，不因个别问题堆积禁令、增加 Prompt 层级或引入新的抽象机制。
- **验证变化**：针对修改目标检查预期行为及可能的回归；如实说明实际验证结果，不将静态审查等同于模型行为验证。

**核心原则：用最小充分的 Prompt 指导模型判断，用代码保证确定性约束；以最小必要改动解决问题，不破坏现有有效行为。**
